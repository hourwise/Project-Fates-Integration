# Fates source-to-control matrix

This matrix maps each external concern to prevention, detection, containment, recovery, audit and residual risk. “Proposed” means no claim of current enforcement.

| Source/concern | Prevention | Detection | Containment | Recovery | Audit | Residual risk |
|---|---|---|---|---|---|---|
| Twin: false causal narrative | Admit derived claims only with source-role/dependency edges, uncertainty and review policy | Contradiction, cycle, missing-source, deployment-state and temporal checks | Keep tentative/quarantined derivations out of action-critical packs | Recompute dependants; preserve supersession history | Record model, prompt/config hash, evidence set, cost and reviewer | Causal inference remains probabilistic; coherent prose can still persuade reviewers |
| Twin: stale inferred context drives action | Ananke live-state gate; memory is never authority | Compare context assumptions with current source/runtime state | Deny with `STALE_STATE`; isolate stale pack | Re-retrieve/recompute, then obtain fresh approval | Link retrieval, live check, decision and execution | Live systems can change after the check; bounded freshness is still required |
| OpenLore: remote docs treated as instructions | Treat as untrusted evidence; pin origin/revision/hash; preflight | Host-key/TLS identity check, content-hash drift, instruction markers | Read-only mount/fetch; derived-only exposure for risky files | Invalidate snapshot and dependent memories | Source URI, revision/hash, identity and fetch receipt | A trusted publisher can still publish incorrect or malicious content |
| OpenLore: scoped-view leakage | Explicit principal/tenant/purpose on every fetch; no ambient mount | Canary/cross-user negative tests and access-denial telemetry | Separate cache keys and context packs per effective scope | Purge caches and derived dependants on revocation | Effective grants and source ACL lineage | Backups/logs/model providers may retain already disclosed data |
| ToolFunnel: gateway bypass | All execution paths terminate at Ananke; gateway hook is defense-in-depth | Bypass-path tests and unmatched outbound-call telemetry | Disable gateway/integration; revoke grants | Re-admit after configuration and origin verification | Gateway plus downstream origin, route, hook and Ananke decision | Local shell/direct network access remains until host-isolated |
| ToolFunnel: origin obscured by alias/wrap | Immutable origin chain and schema/content hashes in discovery/approval | Compare advertised/responding identity; header/body/schema drift | Quarantine route or changed tool | Re-discover and re-approve | Preserve gateway, upstream server, tool alias and translation receipt | Compromised gateway can lie unless independently attested |
| ToolFunnel: stale lean catalogue | Principal/tenant-specific cache; TTL ceiling; forced invalidation | Hash/version/list-change checks | Refuse consequential call on receipt mismatch | Refresh discovery/catalogue | Catalogue receipt linked to approval | Semantic behaviour can change without schema change |
| n8n: untrusted workflow import | Preflight, normalize, inventory credentials/effects, resolve/flag expressions, deny unknown nodes | Static graph analysis, side-effect and composition-risk findings | Quarantine imported workflow; no credentials attached | Re-import pinned revision after review | Source hash, node graph, findings, reviewer and admitted version | Dynamic code and remote subworkflows may evade static analysis |
| n8n: workflow mutation after approval | Bind approval to canonical plan/step graph and dynamic destinations | Re-hash before each consequential step | Suspend and invalidate approval | Re-plan and obtain staged approval | Plan versions and mutation cause | External state may mutate independently after approval |
| n8n: retry/partial success | Persistent idempotency and transaction/compensation declarations | Attempt/effect reconciliation; indeterminate state | Stop downstream steps on unknown/failed effect | Query provider; compensate only under fresh authority | Step, attempt, idempotency, effect and compensation records | Some external effects are irreversible or not queryable |
| OptScale: runaway cost/loop | Hard per-goal cost/token/time/tool/recursion/concurrency/rate budgets | Deterministic counters plus advisory anomaly signals | Cancel workflow, revoke grants, trip tenant/runtime stop | Resume only with explicit new budget/approval | Budget configuration, consumption and stop reason | Cancellation may be cooperative; in-flight external work may continue |
| OptScale: unauthorized resource access | Deny-by-default server/tool/resource allowlist at Ananke | Denial/bypass telemetry and capability drift | Revoke integration/grant; isolate runtime | Re-admit under corrected policy | Both principals, route, scope and policy | Ungoverned direct egress bypasses logical allowlists |
| OptScale: fleet anomaly | Registration and ownership required; deterministic controls remain primary | Goal-level loop/drift/token/tool-pattern signals | Quarantine runtime/agent and stop new work | Operator review and staged re-enable | Incident timeline and model/provider/config changes | Anomaly models produce false positives/negatives |
| MCPHunt: cross-server secret propagation | Flow labels, purpose/destination policy, secret isolation, explicit declassification | Canary/lineage tracking and outbound argument checks | Block write/model call; quarantine leaked context | Rotate secret, invalidate derived/cached objects | Source→transformation→destination lineage and decision | Semantic secrets and aggregates may evade lexical taint |
| MCPHunt: allowed reads+writes form unsafe composition | Plan-level composition decision in addition to per-tool decision | Cross-step reachability and authority-expansion analysis | Split workflow/stage approvals; deny unsafe edge | Re-plan with sanitization or safer destination | Plan graph and risk explanation | Novel compositions may not be recognized in advance |
| Malicious MCP metadata/schema | Metadata untrusted; identity/origin verification; schema hash; preflight | Diff descriptions/schema/capabilities; semantic triage | Hide/quarantine tool and invalidate approvals | Re-admit pinned known-good revision | Registration/discovery receipt and drift event | Benign-looking metadata may conceal malicious implementation |
| Malicious MCP implementation | Sandbox, least privilege, network/secret broker, effect allowlist | Runtime effect evidence and behaviour-versus-intent deviation | Kill process, revoke credentials, quarantine server | Restore workspace, rotate credentials, re-admit clean build | Process/network/file/tool effect evidence | Sandboxes and detectors can be escaped or incomplete |
| Multi-component malicious server | Restrict each component and composed capability | Step-wise trajectory/effect analysis | Stop chain before next consequential edge | Roll back/compensate where possible | Component and cross-component causation | Distributed low-signal attacks may remain below thresholds |
| Hacken Grok/Bankr incident | Untrusted content cannot be authority; no capability expansion from NFT alone; high-value signer/approval; destination/value limits | Preflight flags encoded instruction; live transaction simulation; changed-permission event | Block transfer; revoke agent wallet/tool access | Recover/rotate only where chain/provider permits | Original content, decoded text, capability change, exact transaction and signer | Prompt injection is not solved; a malicious human approval remains possible |
| Content preflight: archive/parser attack | Bounded recursion/size/time, safe parser, path/symlink rules, macros/scripts disabled | Typed findings, partial extraction and parser failure | `QUARANTINED`, `UNSUPPORTED`, `RESOURCE_LIMIT_EXCEEDED`, `INSPECTION_FAILED` | Reinspect with approved parser/profile | Content hash, parser/version, findings and receipt | Parser zero-days and hidden multimodal instructions remain |
| Content preflight: changed content | Receipt bound to byte/content hash and extraction profile | Hash mismatch before exposure/admission/execution | Reject stale receipt | Re-run preflight and downstream admission | Old/new receipts and invalidation event | Mutable remote resources may change during streaming |
| Retrieval: plausible stale answer | Authority/freshness-weighted retrieval and live-source requirement for action | Coverage, omitted contradiction and stale-source reporting | Mark uncertain/stale; block action-critical use | Refresh and replay retrieval | Candidate/selected/omitted sources and rationale | Retrieval can miss unknown evidence outside indexed sources |
| Permissions: jointly sensitive derived fact | Most-restrictive default, ACL lineage, explicit declassification by authorized principal | Joint-sensitivity and cross-tenant tests | Restrict record/context pack; purge caches | Recompute after ACL/revocation change | Contributing ACLs, effective classification and declassification receipt | Inference may reveal facts not explicitly present in sources |
| Provider fallback | Pre-authorized provider/model/region/retention/training policy; no silent fallback | Provider/model-change event and disclosure-policy comparison | Stop or select only equivalent approved route | Retry with preserved budget/idempotency after fresh decision | Selection rationale, provider/model, data classes and costs | Provider policy claims may be stale or unverifiable |
| MCP stateless per-request metadata | Authenticate independently; treat `clientInfo`/capabilities as assertions | Compare verified principal/attestation and request-to-request drift | Deny mismatch or unexplained expansion | Re-authenticate/re-discover | Asserted and verified identities separately | Compromised authenticated workload can still send malicious requests |
| MCP `server/discover` and caches | Discovery receipt scoped by origin/principal/tenant; material drift invalidates approval | Identity/schema/capability/version/hash/permission changes | Reject stale catalogue; quarantine downgrade | Re-discover and re-approve | Discovery/cache receipt and invalidation reason | Server behaviour may drift without catalogue change |
| MCP routing headers | Canonical parse of headers and body; exact equality required | Duplicate/malformed/rewritten/header-body mismatch tests | Reject before policy/execution | Correct proxy and retry as new request | Raw normalized headers plus canonical method/name | Intermediary ambiguity and request smuggling require HTTP-stack hardening |
| MCP MRTR | Treat each retry/input as new governed step; input is not approval | Scope/destination/schema/identity/expiry diff | Suspend or deny unrelated/sensitive request | Resume with fresh input and decision | Round, input provenance, approval and attempt lineage | User/model may supply incorrect but authorized input |
| MCP headless auth | Workload authentication plus bounded delegation and risk-class policy | Attestation, issuer/audience/resource/expiry/revocation checks | Revoke workload/grant; kill scheduled jobs | Rotate keys and re-provision least privilege | Workload, owner/delegator, environment, grant and action | Compromised CI/runtime can act within its valid bounds |
| MCP token passthrough/mix-up | Audience/resource binding; issuer validation; explicit token exchange only | Cross-server token tests and auth-server-change detection | Reject/rotate/revoke tokens | Re-register with verified issuer | Token metadata without bearer value | Malicious discovery metadata can target SSRF/mix-up paths |
| MCP enterprise auth | IdP controls server connectivity; Ananke separately controls tools/effects | Offboarding/revocation and claim-mapping tests | Revoke at IdP plus Fates grants/cache | Re-authenticate/re-admit | IdP assertion, mapping and Ananke decision | IdP compromise or over-broad group policy affects many users |
| Startup readiness race | Distinct process/health/readiness/admission state; no empty-list success cache before ready | First-turn race and duplicate-registration tests | Degraded/unready state; bounded backoff | Retry discovery with same registration idempotency | State transitions, attempts and catalogue receipt | Slow/partially initialized upstream may appear healthy |

## Control ownership

- **Ananke:** final action, information-flow, approval, grant, revocation, budget-stop and declassification decisions.
- **Mnemosyne:** provenance, dependency/ACL lineage, reliability, contradiction, retrieval evidence and invalidation state.
- **Horae:** discovery, origin-preserving routing, plan propagation, durable workflow/task state, attempts, budget counters and lifecycle.
- **Runtime Contracts:** neutral portable envelopes only—never algorithms or decisions.
- **Moirae Code:** protected host, broker/operator UX, disclosure of degraded/ungoverned surfaces, local isolation and enterprise/product projections.
- **Fates Integration:** consumer-driven compatibility and adversarial end-to-end proof at pinned commits.
